# Technical writing guide

Use short sentences, active verbs and fixed terms. Put the action before its reason. State inputs, units, limits and results. Use one instruction per numbered step. Remove claims that have no linked evidence.

| Term | Meaning |
| --- | --- |
| Run | One bounded execution with a recorded identity |
| Checkpoint | Saved state that a named executor can load |
| Stall | No measured progress for a stated interval |
| Failure | A declared operation or check did not pass |
| Correction | A recorded change made in response to evidence |
| Verification | A check of execution or numerical results |
| Validation | Comparison with suitable physical reference data |

Replace vague claims such as robust, seamless or production-ready with measured results. Keep implemented behavior separate from planned behavior.

This guide applies principles from [ASD-STE100 Simplified Technical English](https://www.asd-ste100.org/faq.html). It does not claim dictionary-level compliance. Technical terms such as OpenFOAM, residual and checkpoint remain necessary.
